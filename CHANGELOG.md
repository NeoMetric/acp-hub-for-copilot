# Changelog

## 1.0.1

- New screenshot of the sidebar in the README. Nothing else changed.

## 1.0.0

This release moves the agents out of the extension host into one local ACP Hub server that every window, a browser page and any OpenAI-compatible client share. The extension is a client of that server's API again, the control page shows and sets the server it runs from, and the sidebar draws that same page. The list below is everything that changed since 0.0.6.

- Fix every new chat missing the model's cache for its whole session prompt. Copilot writes the id of the chat's session folder into its system prompt, and the hub passed that on unchanged, so no two chats shared a prompt. The session folder now goes in the message that opens the session, after the cached prompt, and the tool arguments section comes last in the prompt. In a test with Claude, a second new chat read 94% of its first call from the cache instead of 874 tokens. Each new chat logs `Session prompt hash`; the same hash means the same prompt. Codex and Google do not yet share a cache across chats, for reasons in the CLIs, recorded in `docs/prompt-caching.md`.
- Fix stopping a chat during a tool call costing a new session and a cache miss. When the client rewrote the result of a call it had stopped waiting for, the engine took it for an edit of the conversation, closed the session and rebuilt the chat from a transcript in a new one (a 55% hit in the log). A turn that was abandoned and left only tool results behind now goes on in the same session, so its cache still serves the conversation, whichever agent it is. The log lines that show a changed message are now one short line each instead of the whole message.
- Reading the Google quota no longer flashes a terminal window. The Antigravity CLI's hub was started with no console of its own, so the CLI allocated one, and Windows handed that console to the default terminal as a window that appeared and vanished with the read. On Windows the hub now runs behind a hidden `cmd.exe`, whose invisible console the CLI inherits, so it allocates none; nothing about the read changes (same CLI, same port, same token, still killed with its tree).

- **ACP Hub: Sync Models** also writes each model's context window to the CLI's `providers.json`, as `capabilities.limits` (`max_context_window_tokens`, `max_prompt_tokens`, `max_output_tokens`), the same numbers the VS Code model picker shows. Without them the CLI assumed a small default window for these models and compacted the conversation far too early. Run the command again and restart the CLI to pick them up.

- **ACP Hub: Sync Models** also writes each model's reasoning efforts to the CLI's `providers.json`, as `capabilities.supports.reasoning_effort`, so the `/model` picker in Copilot CLI steps through them with the left and right arrows. Only the levels the CLI knows are written (`low`, `medium`, `high`, `xhigh`, `max`); the server's `default` and `ultra` are left out, and a model with none gets no `capabilities`.

- New VS Code setting `acpHub.server.autoStart` (default on). With it off, a window starts no server by itself: it only attaches to one that already answers, and starts one only for a chat message, the sidebar's **Start server** button, or the script run by hand. It is a window setting, so it never reaches `config.json` and the server knows nothing of it. The sidebar's "Server not running" page now shows the `node <extensions folder>/dist/server.js` command to paste in a terminal and points at the setting.

- The VS Code sidebar draws the same page as the dashboard, so the strip with `127.0.0.1:<port>` and its green dot, the link that opens the dashboard in a browser, and the **Server settings** view now appear there too; the webview transport had been dropping the server's own view from every snapshot. When the sidebar reaches no server it says **Server not running**, with the reason and a **Start server** button that starts one as a click does, clearing a stop recorded by **ACP Hub: Stop Server**. The Docs view's **Server** section now says when a window starts the server, and names the `node "<extensions folder>/.vscode/extensions/neometric.acp-hub-for-copilot-<version>/dist/server.js"` command that runs it in a terminal with no window open.
- The control page shows the server it runs from: a strip at the top with `127.0.0.1:<port>`, a link that opens the page in a browser with the token in it, and a green dot while the server answers (red when it does not). A **Server settings** view sets the port, which is saved in `config.json` as `server.port` and read when the server starts (`ACP_HUB_PORT` still wins); a **Restart server** button, with a note that it ends any existing sessions, applies it. A new **Docs** view, after Usage, explains the server and its settings, the VS Code Copilot client and **ACP Hub: Sync Models**, and the Copilot CLI, in collapsible sections. The window now looks for the server on the saved port instead of always `8791`.
- Upgrading keeps the agents' settings. The previous version read `acpHub.agents.<id>.*` (including **Enabled**) and `acpHub.resume.*` from the user's own settings; the server reads `config.json`, so the first activation copies what the user saved there, once. A value `config.json` already has wins, and a failed copy is tried again on the next activation. Without it an agent the user had switched off would have started with the window. Only values saved in your user settings are carried: one saved in a workspace's `.vscode/settings.json` is not, since the hub's `config.json` is one file for the machine. The settings the extension no longer contributes stay in `settings.json` and now show there as deprecated, each saying where its value lives; the first run after the upgrade names them in the **ACP Hub** log.
- New defaults for a setting nobody has saved: idle session timeout 1800 seconds, idle agent shutdown 120 minutes, Claude tool search on and default thinking effort medium for every agent. Claude has a **Max live chat sessions** setting (8 by default), since every live chat holds its own Claude process.
- Token usage is normalized: fresh input excludes cached tokens and output counts thinking once, so a turn with thinking is no longer counted twice in the usage chart. The Usage view notes that only Claude reports cache writes.

- The control page has a **Usage** view: a stacked area chart of what the turns spent, in fresh input, cache read, cache write and output tokens, over today, 7 days, 30 days or the whole retained window, filterable by agent and by workspace and switchable between them without a round trip. **Keep history for** sets the retention (1 to 365 days, 30 by default) and deletes the older days when lowered. The server writes one small file per day under `usage/` in the store root, reads them back at startup, and records nothing on the chat path: a turn costs a few additions and the file is written a couple of seconds later. History starts with this version; usage from before was never stored.

- The Models view of the control page has **Refresh** in place of **Sync**: it reads the agents' models again and writes nothing, and saving a name only stores it. The Copilot files are now written by the new **ACP Hub: Sync Models** command, which refreshes the models, writes the CLI's `providers.json` and the provider headings in the extension's `package.json`, re-lists this window's providers and offers a window reload when a heading changed. The server no longer knows either file, so a browser page or any other client of the API stays Copilot-free.

- The agent cards take an API key. **Use API key** (or **Replace API key**) opens a masked field beside **Sign in** on Claude, Codex and Google; the key is saved by the server, the agent restarts with it, and **Auth preference** in the card's settings still picks the key or the account when both exist. Before, the page offered no way to type a key.
- The settings text no longer names Copilot, VS Code or the extension: it says "the client" and "the server".
- The Google card drops **Agent command**, **Agent arguments** and **Use the agent's built-in tools**. The agent always runs the downloaded Antigravity CLI with its own tools off; a value left for them in `config.json` is ignored.
- **Dump requests** works on the server again: with it on, each request is written to `<root>/agents/<id>/requests` as a JSON file.

- **ACP Hub: Stop Server** now sticks. The stop is recorded in `server.stopped` in the store root before the server is asked to close, so every window of every folder sees it during the shutdown and none starts a server afterwards: a sidebar that reconnects, a check of a server that died, and a window that opens merely attach to a server that answers, and a chat that fails no longer restarts the one the user stopped. The record is taken back when the stop fails, and the next chat or sidebar action clears it and starts the server as before.
- Split the extension's output into two channels: **ACP Hub** shows only what the window itself does, and the new **ACP Hub Server** mirrors the server's own lines, from `server.log` or a child's stderr, at the levels the server named. A window that attaches to a server another window started now shows the last 256 KB of `server.log` before following it live, so every window shows the same request lines; **ACP Hub: Show Server Logs** opens it. The window also logs when Copilot asks a model for a reply and how long reaching the server, building the request and waiting for the first event took, at info and debug level, and the server logs one debug line per chat request with its model, message count, size and how long reading it took.
- The server's chat route is a strict OpenAI chat-completions server now: `finish_reason` is only `stop`, `length` or `tool_calls`; a turn that fails is one `error` chunk followed by `[DONE]`, with no finish; the usage of a stream is sent only when the body asks for it with `stream_options.include_usage`, as a final chunk of its own with no choices; `/v1/models` entries carry `created`; and the server itself maps `response_format`, `tool_choice: "required"`, the legacy `functions`, and replaces an attachment its agent cannot read with a note saying so.
- The extension is a plain client of that API again: it asks for the figures of the turn, reads them from the final chunk, takes a failed turn's `error` chunk as the error, treats a reply that stops before `[DONE]` as cut, and sends message content as parts. The code that only worked around the server's older replies — the `finish_reason: "error"` reply, a reply that ended without `[DONE]`, the usage folded into the finish chunk, and the content joined into one string — is gone.
- A chat that is sent again unchanged, as a client does to retry or regenerate, is answered again instead of failing with "There is no user message to send"; the engine treats it as an edit of the last turn. The server also answers `GET /v1/models/<id>`, the unversioned `/models` and `/chat/completions`, `OPTIONS` preflights, and `405` for a wrong method, and an open stream sends a keep-alive comment every 15 seconds.

- One agent process per agent, run in `<root>/agents/<id>/workspace`, serves every chat and every folder, with a session per chat; the agents' own tools are off and the session prompt carries the chat's real folders, so the folder the agent runs in decides nothing a chat sees. The process starts with the server's first read of the models or first chat, and stops only when it goes idle. Tried with Claude, Codex and Google through the server: chats from two folders shared one process each, and each agent named the project folder the request's guidance gave it.
- The extension's settings are down to `acpHub.server.idleTimeoutMinutes`, `acpHub.server.detached` and `acpHub.server.autoStart`. The port is the server's own, saved in `config.json` as `server.port`; agents are always started when a window connects, and one process per agent is the only process model, so `acpHub.server.port`, `acpHub.server.warmAgents` and `acpHub.server.sharedAgents` are gone; a value left for them in `settings.json` is ignored.
- A stock client's own system (or developer) message is now the guidance a new session opens with, so it can tell the model which workspace it works in; before, only the extension's `acp.systemGuidance` was forwarded. A request that carries `acp` extras, which is what the extension sends, is unchanged.
- A window that connects to the server now asks it to start every enabled agent (`POST /v1/warm`), so the first chat no longer waits for them. The route names no folder: every chat is served by the agent's one process.
- The detached server now runs on its own Node.js (on PATH, else Node.js 22 downloaded once into `<root>/node` and checked against nodejs.org's checksum) instead of a copy of VS Code's executable, so ending VS Code's processes no longer ends it; VS Code's executable remains the fallback. Every window keeps showing the server's log lines in the ACP Hub output channel for as long as the server runs, including a window that only attached to it.
- Run the server a window starts outside VS Code instead of as a child of the window, so it survives closing or reloading a window, every window shares it, and agents stay warm (the first chat after a reload no longer waits for them to start). It logs to `server.log` in the store root, closes itself, agents included, after `acpHub.server.idleTimeoutMinutes` (default 30; `0` keeps it running) without any window using it, and can be closed at once with **ACP Hub: Stop Server**, which calls the new `POST /shutdown` route (bearer token required). The first window after an extension update replaces a server left running by an older version. Turn `acpHub.server.detached` off to keep the old behaviour, a server that exits with its window.
- Remove the limit that used to cap agent processes, and the per-folder process model with it: an agent runs as one process for its whole life.
- Fix `claude auth status returned unparseable output` in the log, and the account and usage not refreshing from it. The preload that hides console windows replaced `child_process.execFile` without the `util.promisify.custom` hook, so the agent read the output of every command it ran as empty.
- Fix a question the agent asks the user being lost when it is answered more than two minutes later. The server failed every parked tool call after 120 seconds, told the agent it had timed out, and ended the turn with a reply no client could see; the answer then arrived for a call the hub no longer held and was refused with `400 No tool call … is waiting for a result in this chat`, which the client retried five times and reported as a failed request. A parked call now waits as long as its agent's own policy allows, which is the wait the sidebar has always given it (unbounded for Claude, Codex and Antigravity), and a result whose call had already been given up on is answered as the user's next message instead of being thrown away.
- Fix installing an update of the extension failing with `EBUSY` while ACP Hub is running. The server a window started used the extension folder as its working directory, and Windows does not rename a folder that is a running process's working directory, so the installer could not replace the old version. The server now runs from the shared store and is told the extension folder in `ACP_HUB_EXTENSION_DIR`, which also lets a hand-started server point at a checkout.
- Add the setting **Default thinking effort** to Claude (High unless changed), Codex and Antigravity (Default, the agent's own choice, unless changed); each agent keeps its own value. A request that names no effort, such as a subagent started with the task tool, or that is left on the picker's Default, used to run at whatever the Claude agent picked, which could be Max for Sonnet and cost a lot of tokens. It now runs at the configured effort; an effort chosen in the picker is kept, and the setting `Default` restores the old behaviour.
- Fix the ACP Hub output channel showing the time twice and offering no way to filter by agent. The server's own timestamp and level are now taken off before the channel adds its own, and every line an agent's chat service writes starts with `[<agentId>]` again (for example `[claude]`), so typing `[claude]` in the output filter shows only that agent.
- Add a Models page to the control page, to choose the provider name of each agent and the name of each model as the VS Code and Copilot CLI model pickers show them. The provider name is shown in bold with one pencil that opens the provider name and all of that agent's model names for editing together (Save, Cancel, Enter and Escape), and a progress bar shows while Sync fetches the models. Saving a name, or pressing Sync (which also fetches the agents' current models), writes the CLI's `providers.json` (`~/.copilot`, or `COPILOT_PROVIDERS_CONFIG`) and the provider `displayName` entries of the extension's `package.json`, and the server publishes the chosen model names; the page then asks you to reload the VS Code window and restart the CLI. Entries in `providers.json` that the server did not write are kept. An installed extension loses the `package.json` change when it updates, and `npm run generate` resets it; press Sync again. This replaces `scripts/sync-copilot-models.ps1`, which is removed.
- Let a browser use the control page without sending a header: a hand-started server prints `http://127.0.0.1:<port>/?token=<token>`, which sets an `HttpOnly`, `SameSite=Strict` cookie and redirects to `/`. The bearer header still works for API clients, and a server started by a window does not print the token.
- Run every agent in a local ACP Hub server instead of in the extension host. The extension is now a client of that server: on activation the window attaches to the server answering on `127.0.0.1`, and when nothing answers it starts one (`dist/server.js`, shipped in the VSIX) as a child of the window. Every window of the machine uses the same port, so they share one server; a server started by a window exits with it, and the next window starts its own. Agent settings now live in the sidebar and in `<root>/config.json` (`~/.acp-hub`, or `ACP_HUB_HOME`); values already under `acpHub.agents.*` in `settings.json` are not migrated, so they no longer have any effect. Sign-in follows the server's flow — a page URL to open, or the command to run in a terminal — instead of a VS Code quick pick. Saved API keys are carried over once into the shared store's `secrets.json` (written `0600`, readable by your account only); the copy in VS Code's secret storage is left as it is.
- Add `acpHub.server.port` (default 8791) and `acpHub.server.autoStart` (default on), the only settings the extension itself keeps. A change to either applies after a window reload. The bearer token both sides use is kept once in `<root>/server.token`.
- Known losses with the server-only runtime: a window regaining focus no longer wakes an agent the idle shutdown stopped (the next message starts it), and the "Dump requests" setting has no effect, because requests no longer pass through the extension host.
- Fix an upgrade from a version that kept its agents in the extension's own storage making every installed agent look missing (and downloading it again). On the first activation the extension moves `<globalStorage>/<agentId>` into the shared root both gateways read, `<root>/agents/<agentId>` (`~/.acp-hub` or `ACP_HUB_HOME`). An agent the shared root already has is left as it is, a folder is only removed once its contents are in place (a move across volumes copies, then deletes, and a copy that fails keeps the original), and nothing moves when the shared root fell back to the extension's own storage. The move is recorded under `acpHub.installsMigrated`, so it runs once; a move that fails runs again on the next activation.
- Fix copying a Google chat making the chat it was copied from miss the cache. A copy used to take the source's session id, and the source chat moved onto a copy with a new id, so the chat you were not working in paid the miss (and the rewind of the source could fail with `step_index out of bounds`, sending the copy to a transcript as well). A copy now gets a session id of its own, which misses once because Antigravity writes the id into its system prompt, and the chat it came from is left alone: its session is no longer closed and resumed for the copy, which made the agent send the whole conversation uncached (a 0% hit on 32,848 tokens in the log), so it goes on in the session it had. Editing an earlier message in a chat still keeps the chat's own session id. When an edit cannot keep it because another chat is mid-turn, the log now says so.
- Fix, for the Google agent only (Claude and Codex are unchanged), editing an earlier message (or resuming a chat) missing the prompt cache for the whole conversation when Copilot's guidance had changed in between, even by one line. The session prompt is rebuilt from that guidance and leads the conversation, so the agent saw a different first token and re-read everything uncached (the log showed `0 cached` for the first turn after the fork). The extension now keeps the prompt each saved session began with, in its storage folder, and sends that same text when it resumes or forks the session; what changed in the guidance still reaches the agent as a message. Prompts unused for 14 days are removed. Chats saved before this change have no stored prompt, so their first edit can still miss. Switching to a mode that adds a tool (such as Autopilot's `task_complete`) still misses once, because the tool declarations come before the conversation in the model request.
- Fix the first message to Codex waiting several seconds, up to 18 in one window, after the agent was stopped for being idle. On start Codex refreshes its model catalog and checks the account with ChatGPT before it answers the adapter's account read, which every new session waits for; a connection that stalls holds that up for 5 seconds or more. An agent the idle shutdown stopped now starts again, with its warm session, as soon as the window is in use again, so the start runs while you type.
- Run the Google agent on the Antigravity CLI's own ACP server (`agy acp`) instead of the separate Antigravity ACP server. It uses the same model backend as the official Antigravity extension, so turns are about as fast: the same eight-step test went from about 2 minutes 14 seconds to about 50 seconds (51 seconds in the official extension). The extension downloads the CLI, checks it against Google's published SHA-512, and fetches the new version unasked after an extension update; the old server's files are removed. Chats started on the old server continue from their transcript once.
- Fix the thinking level of the model picker not controlling the Google agent: on the old server even Low thought for thousands of tokens on some steps. Low now does no extended thinking, and a reopened chat gets its level back.
- Fix the first turn of an edited or forked Google chat missing the prompt cache. Antigravity writes the conversation id into its system prompt, so a copy under a new id could not reuse it. The fork now keeps the source's id: the whole conversation is copied for the original chat, which continues there, and the source is rewound to the fork point without touching workspace files. The agent is restarted at the fork, which is when it re-reads the conversation; opening a Google chat or resuming one after a window reload stays at a few milliseconds. A fork taken while another Google chat is in the middle of a turn keeps an id of its own instead of restarting the agent, so that fork's first turn misses the cache once.
- Stop a terminal window flashing open while the extension loads, on Windows. The Google quota is read through a language server that `agy --hub` starts, and the process that server runs in opens a console window of its own, which Windows Terminal shows for as long as the read lasts, whatever the extension asks of the process. The quota is now read only when asked for (the Refresh usage button, or after signing in) instead of at startup and after every turn. Forking a Google chat still starts that server for a few seconds.
- Make forking a Google chat survive the CLI's language server not being ready: it sometimes answered the copy or the rewind with `failed to clone trajectory` or `unknown model key …`, which made the chat fall back to a transcript in a new session (a full cache miss). Those answers are now retried a few times, and a copy made for a fork that then failed is deleted instead of piling up in the CLI's history. Measured on the CLI (1.5.3): after a fork the first model call of the chat that keeps the id still sends the earlier turns' history uncached (the CLI re-renders a rewound conversation), so a fork's first turn cached about 45–60% on a long chat and the next calls about 96%; that part is the CLI's.
- Turn Antigravity's own tools off for real, instead of asking the model not to use them. The CLI ignores the agent's `disabledTools` and the `_meta` options for this, but the custom agent file it loads honours a `tools` allowlist, so the extension now runs `agy acp --agent=acp-hub-copilot` with `tools: []` whenever the built-in tools are off (the default). In a real chat the CLI then offered only the chat's own tools, `list_resources` and `read_resource` — no `run_command`, `read_file`, `write_file` or `edit_file` — and the first request carries about 4,700 fewer tokens. "Use the agent's built-in tools" still runs Antigravity's own agent with all of its tools.
- Add the "Replace the Antigravity system prompt" toggle to the Google agent card, like the one Claude and Codex have. Antigravity generates its prompt, and a custom agent replaces its identity section rather than sitting beside it, so the agent keeps a short Antigravity persona when the toggle is off and takes Copilot's identity when it is on; Copilot's guidance follows either way, and the sections about skills, artifacts and messaging stay. The agent file lives in the CLI's global agents folder (`~/.gemini/agents/acp-hub-copilot/agent.md`) and appears in its agent list; forking and its prompt-cache hits are unchanged.
- Fix the Google agent's context figure in the chat's session info, which grew with every tool call: `agy acp` sends no `usage_update` and reports only the sums of a whole turn, and every model call of a turn sends the whole conversation again, so a turn of three calls showed about 76K tokens for a 26K context and a long turn reached 352K. The extension now reads the tokens of the last model call from the CLI's own record of the conversation (`<gemini home>/antigravity-copilot/brain/<session>/.system_generated/logs/transcript.jsonl`, which carries `input_tokens` and `cache_read_tokens` per call) and reports that as the context, with its cached share. Agents that do send `usage_update` are unchanged.
- Show the Google agent's cache hit rate, which the CLI reports.
- Read the Google quota from the Antigravity CLI instead of asking the agent for `/usage`.
- Remove the "Antigravity CLI (agy)" setting: edits, `/fork` and side chats now use the CLI the agent runs. The "Agent command" setting now points at an Antigravity CLI.

## 0.0.6

- Continue edited and forked chats from a saved conversation checkpoint when the agent supports it. Antigravity requires the separately installed Antigravity CLI; otherwise the chat is rebuilt from its transcript.
- Fix Antigravity taking minutes over a few steps of a turn. The agent saves a tool result of about 4,000 characters or more, such as a file read in full, to a file and hands the model only the path. With its own file tools off, the model then reasoned for 4,000 to 20,000 tokens about how to get at the content. Results are now cut to 3,500 characters with a note on how to ask for the rest, and the same eight-step test went from about 3.5 minutes to about 1 minute.
- Fix an answer to a question never reaching Codex. Codex's `exec` tool yielded after 30 seconds, before the user had answered, and the agent went on without reading the answer. It now stays open for up to 30 minutes, and a yield time set in `CODEX_CONFIG` is kept.
- Fix an answer to a question that took longer than 5 minutes being lost with "timed out awaiting tools/call after 300s". Codex now gives a call to the Copilot tools up to 24 hours, set in the `config.toml` of the extension's own Codex home. The extension keeps that file up to date until its first line is removed.
- Fix an answer to a question never reaching Claude when the user took several minutes. Claude Code closes a silent tool notification stream after about 6 minutes and then drops the pending call ("transport dropped mid-call"). The bridge now keeps the stream alive.
- Fix every `/usage` read leaving a Claude Code session behind in `~/.claude/projects`, which filled the session list of tools that read that folder with `/usage` entries. The session that reads usage and the model list is now ephemeral and keeps no transcript. Sessions already left behind are not touched.
- Number the model calls of a turn in the log for agents that report only the turn's cache split, with the context each call sent, and say how many calls the turn's cache figure adds up, so a low-looking cache percentage on a long turn can be traced to its calls.

## 0.0.1

Initial release of ACP Hub for Copilot.

- Use Claude, Codex, and Antigravity agents in GitHub Copilot Chat through ACP adapters.
- Install, sign in to, and configure agents from the sidebar.
- View available usage limits and cache hit rates.
- Authenticate using supported provider accounts or API keys.
