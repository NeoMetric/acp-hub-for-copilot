# HTTP Host (chat-completions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Serve the engine over HTTP as an OpenAI-compatible chat-completions endpoint, sharing the extension's code and storage, without shipping server code in the VSIX.

**Architecture:** `src/hosts/http` implements `HostPort` headlessly. `src/composition/headless.ts` wires adapters + `ChatService`. `src/main/server.ts` is the second esbuild entry, emitted to `server-dist/`. The HTTP client executes tools: the endpoint returns `tool_calls`, the client re-posts results.

**Spec:** docs/superpowers/specs/2026-11-09-two-host-core-design.md (sections "The HTTP host", "Tool calls across two hosts", "One store, two gateways", "Packaging isolation").

## Global Constraints

- `src/engine/**` keeps zero `vscode` imports; the server imports nothing from `src/hosts/vscode`.
- `npm run package` must not contain `server-dist/**`; CI fails if it does.
- No new dependencies unless unavoidable; Node's `http` is enough.
- Everything ends with `npx tsc -p . --noEmit`, `npm run lint`, `npm test` green.

## Review Focus

- **A client that never sends `x-chat-id`.** Two conversations must not collide, and a re-post must find the same session.
- **A tool call re-posted with a mismatched `call_id`.** It must be rejected, not silently resume the wrong turn.
- **A streaming client that disconnects mid-chunk.** The turn must be cancelled and the session released.
- **Two concurrent requests on different chats.** Sessions must not interleave output.
- **An agent that is not installed.** `/v1/models` and completions must return a clear error, not hang.
